# doc2html

Конвертация PDF/EPUB/XPS/MOBI/FB2/CBZ/изображений (всё, что открывает
PyMuPDF) в HTML/Markdown/txt с сохранением картинок. Подробности —
[readme.md](readme.md). Единственный рабочий файл — `doc2html.py`.

## Тестирование при разработке

- Реальные книги лежат в `input/` (не коммитятся, см. `.gitignore`).
- `conda run -n pdf2html python ...` иногда падает на Windows с
  `UnicodeEncodeError`/`CONDA_NO_PLUGINS` при выводе кириллицы — надёжнее
  звать интерпретатор окружения напрямую:
  `C:\Users\Lopat\miniconda3\envs\pdf2html\python.exe doc2html.py ...`
  (и `export PYTHONIOENCODING=utf-8` в Bash-сессии).
- **После любой правки формата/схемы блоков — гонять
  `tests/regression_check.py`** (тот же интерпретатор, что выше):
  `python tests/regression_check.py`. Запускает реальную конвертацию (с
  OCR) страниц 3, 4, 10, 11, 22, 25, 28 книги «Веб-дизайн книга Якоба
  Нильсена.pdf» и проверяет структуру JSON — каждая проверка привязана к
  конкретному найденному и исправленному багу (ложные колонки на стр. 3,
  заголовки на стр. 4/10, врезка на стр. 11, фрагментация слов на стр.
  22, отступы списка на стр. 25, разрыв слова на стр. 28). Само пропускает
  себя, если книги нет локально.
- Для разовой ручной проверки конкретной страницы —
  `--start-page N --end-page N --restart --no-clean-state
  --generate-alt off` в отдельную scratch-папку `-o`, не в реальный
  `output/` пользователя.

## Бэклог форматирования (по приоритету)

Источник — аудит 4 книг из `input/` + постраничная проверка 12 случайных
страниц против оригинала (агенты реально гоняли `page.find_tables()`,
`get_links()`, разбирали флаги спанов — не предположения). Полный отчёт с
цитатами и номерами страниц: см. историю сессии (артефакт «Аудит
форматирования — doc2html»).

- [ ] **Таблицы.** `page.find_tables()` нигде не вызывается — строка
  таблицы превращается в россыпь несвязанных `<p>` по одной ячейке. В
  ci_sharp.pdf — 26 таблиц, в Konovalenko — 5. Новый тип блока `"table"`,
  рендер как `<table>`/pipe-table.
- [ ] **Блоки кода/листинги.** Код склеивается в одну нечитаемую строку
  без отступов (`//`-комментарий может «съесть» следующую строку). Сигнал
  — подпись «Лістинг/Листинг N.N» + смена шрифта на моноширинный (имя
  шрифта не всегда надёжно — в ci_sharp он анонимный подмножественный).
  Новый тип блока `"code"`, рендер `<pre><code>` без join по пробелу.
- [ ] **Сегментация и разметка списков.** Не только отсутствие
  `<ul>/<li>` — реальный баг: пункт списка иногда сливается со следующим
  несвязанным абзацем, иногда сам раскалывается на два блока (PDF-блок
  под-сегментировать по `^\d{1,2}\.\s`/буллету). Затронуто и в OCR-, и в
  чистом пути.
- [ ] **Курсив/полужирный внутри абзаца.** Сейчас `extract_block_raw_text`
  просто склеивает текст спанов, стиль отбрасывается. По флагам
  (`flags&2` italic, `flags&16` bold) оборачивать прогоны в
  `<em>`/`<strong>` (`*`/`**` в Markdown).
- [ ] **Ссылки.** `page.get_links()` не вызывается — молча теряются (в
  Non-Designers 741 ссылка, некоторые — единственное место, где вообще
  напечатан URL). Внешние → `<a href>`, внутренние → якорь на `#page-N`.
  Для OCR-страниц — хотя бы regex-автолинковка URL в уже извлечённом
  тексте.
- [ ] **Верхние индексы + баг сносок.** `flags&1` → `<sup>` (степени,
  маркеры сносок). Отдельно найденный баг: сноска на стр. 16
  Konovalenko попадает в `margin` (колонтитул) вместо тела страницы —
  чинить независимо от добавления `<sup>`.
- [ ] **Безрамочные врезки + `find_callout_boxes` в «чистом» пути.**
  Детектор врезок по векторной рамке — мёртвый код для документов с
  целым текстовым слоем (вызывается только внутри OCR-fallback). Плюс
  текстовый триггер по метке («ПРИМЕЧАНИЕ»/«ВНИМАНИЕ»/«СОВЕТ») как
  альтернатива рамке для книг вроде ci_sharp.

Отдельно (не баг, для контекста): OCR-точность на «Нильсене» — все 3
случайные OCR-страницы дали серьёзные проблемы (путаница букв о↔o, в↔B,
склейки слов) — это потолок точности EasyOCR на этом шрифте, не ошибка
вёрстки/сегментации. Не в этом бэклоге.
