# pdf2html

Конвертация PDF-документа в читаемый HTML (UTF-8) с сохранением картинок.

Решает типичные проблемы «наивных» конвертеров:

- **Кодировки.** Текст извлекается через PyMuPDF, нормализуется (`NFKC`)
  и очищается от «мусорных» символов Private Use Area. Если у PDF
  сломана ToUnicode-таблица шрифта (текстовый слой в принципе
  нечитаем — глифы маппятся в управляющие символы, а не в буквы),
  скрипт это автоматически детектирует и распознаёт такую страницу
  через офлайн-OCR (EasyOCR, ru+en) вместо битого текстового слоя.
  Результат всегда валидный UTF-8.
- **Картинки.** Встроенные изображения рендерятся из PDF в исходном
  виде (с учётом ориентации/трансформаций, которые PDF применяет при
  отрисовке — иначе картинка может выйти перевёрнутой или зеркальной)
  и сохраняются в подпапку `images/`.
- **Колонтитулы.** Короткий текст в верхних/нижних ~9% страницы
  (номер страницы, название главы) распознаётся как колонтитул и
  выносится в отдельную маленькую строку `.page-meta`, а не вклинивается
  в середину абзаца.
- **Диапазон страниц, потоковый вывод, продолжение прерванной
  конвертации.** HTML пересобирается после каждой обработанной
  страницы — файл можно открыть прямо во время работы скрипта.
  Повторный запуск с теми же (или другими) параметрами `-o`/PDF
  автоматически пропускает уже готовые страницы.

## Установка

Требуется установленный conda (Miniconda/Anaconda).

```bash
install.bat
```

Создаст conda-окружение `pdf2html` (Python 3.11) и поставит базовые
зависимости из `requirements.txt` (PyMuPDF, Pillow, torch, easyocr) —
их достаточно для конвертации без подписей (по умолчанию) или с
`--caption-backend lmstudio`. Модель EasyOCR (ru+en, ~100 МБ) скачается
один раз при первом обращении.

Офлайн-бэкенд подписей `--caption-backend blip` требует пакет
`transformers` — он **не ставится по умолчанию** (это отдельная
зависимость только под BLIP, ничего больше от неё не зависит).
Поставить его можно двумя способами:

```bash
REM Сразу при установке
install.bat --with-blip

REM Или потом, в уже созданное окружение
conda run -n pdf2html python -m pip install -r requirements-blip.txt
```

Сами веса модели BLIP (~1 ГБ) скачаются один раз при первом реальном
вызове `--caption-backend blip --generate-alt`.

## Активация окружения

```bash
activate.bat
```

## Использование

```bash
python pdf2html.py input\example.pdf -o output
```

### Параметры

| Параметр | По умолчанию | Описание |
|---|---|---|
| `input_pdf` | — | Путь к исходному PDF-файлу (обязательный) |
| `-o`, `--output-dir` | `output` | Папка для результата |
| `--save-images` / `--no-save-images` | включено | Сохранять картинки в `<output>/images` |
| `--generate-alt` / `--no-generate-alt` | **выключено** | Генерировать описание картинки (самый быстрый режим — без этого флага) |
| `--start-page N` | 1 | Первая страница для конвертации (1-индексация) |
| `--end-page N` | последняя | Последняя страница, включительно |
| `--restart` | выкл | Игнорировать сохранённое состояние и начать заново |
| `--gpu` / `--no-gpu` | автоопределение | Использовать GPU (CUDA) для OCR/подписей |
| `--caption-backend` | `blip` | `blip` (офлайн) или `lmstudio` (локальный сервер) |
| `--lmstudio-url` | `http://localhost:1234/v1` | Адрес сервера LM Studio |
| `--lmstudio-model` | — | Имя vision-модели в LM Studio (обязательно для `--caption-backend lmstudio`) |

### Поведение флагов сохранения картинок

По умолчанию (`--save-images`, без `--generate-alt`): `<img src="images/...">`
сохраняется, но `alt` пустой — самый быстрый режим, без запуска моделей.

- `--save-images` (вкл) + `--generate-alt`: `<img src="images/...">`
  с содержательным `alt="..."` (описание картинки).
- `--save-images` (вкл) + без `--generate-alt` (по умолчанию): `<img>`
  сохраняется, но `alt` пустой.
- `--no-save-images` + `--generate-alt`: картинка не сохраняется,
  вместо неё в текст вставляется абзац `[Изображение: <описание>]`.
- `--no-save-images` + без `--generate-alt`: картинка не сохраняется,
  вместо неё — заглушка `[Изображение]`.

### Диапазон страниц, потоковый вывод и продолжение конвертации

```bash
REM Только первые 50 страниц
python pdf2html.py input\book.pdf -o output --end-page 50

REM Продолжить с 51-й - готовые 1-50 не трогаются, просто дописываются
python pdf2html.py input\book.pdf -o output --start-page 51
```

- После каждой обработанной страницы итоговый `output\book.html`
  переписывается целиком (атомарно) — можно открывать и обновлять
  прямо по ходу работы скрипта.
- Если скрипт прервать (Ctrl+C, сбой, перезагрузка) и запустить снова
  с той же папкой `-o`, он сам найдёт уже готовые страницы (в скрытой
  папке `output\.<имя PDF>.pdf2html-state\`) и продолжит с места
  остановки — конвертировать заново не нужно.
- Диапазон страниц в повторном запуске может отличаться от первого —
  так можно скармливать книгу по частям вручную.
- Если между запусками поменять `--save-images`/`--generate-alt`,
  скрипт откажется молча продолжать (эти флаги меняют формат уже
  сохранённых страниц) и попросит либо `--restart`, либо новую папку
  `-o`.
- `--restart` игнорирует сохранённое состояние и пересчитывает
  запрошенный диапазон заново (изображения и HTML перезаписываются).

### GPU и LM Studio

`--gpu`/`--no-gpu` включает CUDA-ускорение для EasyOCR и BLIP через
`torch.cuda` — работает только с NVIDIA-картами. **Если видеокарта не
NVIDIA (например Intel Arc/Iris Xe с OpenVINO), этот флаг не поможет**
— PyTorch на CPU-сборке CUDA не увидит независимо от флага.

В этом случае для подписей к картинкам можно использовать локальный
сервер **LM Studio** с vision-моделью — многие раннтаймы LM Studio
умеют ускоряться на GPU разных производителей, не только NVIDIA:

1. В LM Studio загрузите vision-модель (принимающую изображение на
   вход, например `LFM2.5-VL`, `Qwen2-VL`, `InternVL`) и включите
   Local Server (по умолчанию `http://localhost:1234`).
2. Запустите конвертацию с этим бэкендом:

```bash
python pdf2html.py input\book.pdf -o output ^
    --caption-backend lmstudio --lmstudio-model lfm2.5-vl-450m
```

Если сервер недоступен или модель не указана/не найдена, скрипт
сразу останавливается с понятной ошибкой (со списком доступных в
LM Studio моделей), не тратя время на конвертацию текста впустую.

**OCR намеренно не переведён на LLM/LM Studio.** Для дословного
распознавания текста книги офлайн-OCR (EasyOCR) — правильный
инструмент: языковая модель для этой задачи рискует незаметно
перефразировать или «додумать» текст, что для оцифровки книги
недопустимо. LM Studio используется только там, где приблизительное,
творческое описание уместно и полезно — для подписей к картинкам.

### Пример

```bash
activate.bat
python pdf2html.py "input\Веб-дизайн книга Якоба Нильсена.pdf" -o output
```

Результат: `output\Веб-дизайн книга Якоба Нильсена.html` и, если
включено сохранение картинок, `output\images\*.png`.

## Известные ограничения OCR-восстановления

Когда текстовый слой PDF сломан и используется OCR, восстановление
исходной вёрстки — эвристика, не точная наука:

- **Перенос слов через дефис** ("бо-\nлее" → "более") исправляется
  автоматически.
- **Оглавления и указатели** (колонка с номерами страниц отдельно от
  названий) OCR-детектор текста нередко видит как два разных блока
  из-за разреженного пунктирного разделителя — сопоставить название
  с его номером надёжно не получается. Такие «числовые» абзацы не
  выбрасываются, а помечаются классом `.ocr-numbers` (блёкло-серым,
  курсивом), чтобы не выглядеть как обрыв текста.
- **Боковые колонки/врезки** (текст сбоку от основной колонки на той
  же высоте страницы) могут вклиниться в основной текст — колонтитулы
  (верх/низ страницы) отделяются надёжно, а произвольная многоколоночная
  вёрстка внутри страницы — нет, это потребовало бы полноценного
  анализа макета страницы.
- Изображения перед OCR закрашиваются, чтобы текст интерфейса/надписи
  на скриншотах не попадал в основной текст как «шум».

## Примечания

- Описания картинок через BLIP генерируются на английском языке;
  через LM Studio — на языке, который выберет загруженная модель
  (зависит от промпта и самой модели).
- Первый запуск с `--generate-alt`/OCR будет заметно медленнее из-за
  загрузки весов моделей; при повторных запусках модели берутся из
  локального кеша.
- Для больших PDF (сотни страниц) OCR и генерация подписей — самые
  медленные этапы на CPU; отключайте `--generate-alt`, если описания
  не нужны, либо используйте `--caption-backend lmstudio` с GPU.
